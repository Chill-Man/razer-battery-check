# Basilisk Pulse

Лёгкое нативное приложение для **Razer Basilisk V3 Pro и Basilisk V3 Pro 35K** на Windows 10/11 x64. Процент заряда виден на значке трея. ПКМ или ЛКМ открывает компактную панель с зарядом, состоянием зарядки и приблизительным временем до 1%.

## Запуск

Готовая программа: `dist\BasiliskPulse.exe`. Не требует установки библиотек, прав администратора или запущенного Synapse. Windows обычно помещает новый значок под стрелку скрытых значков возле часов. Наведите на число для краткой подсказки, нажмите ПКМ для панели. Щелчок вне панели или Esc закрывает её; приложение продолжает работать. «Выйти» завершает приложение.

`install.ps1` копирует программу в `%LOCALAPPDATA%\Programs\BasiliskPulse` и создаёт ярлык «Basilisk Pulse» в меню «Пуск». Автозапуск включается в настройках панели. `uninstall.ps1` удаляет установленную программу, ярлык и её запись автозапуска; история и предпочтения сохраняются.

## Прогноз

- Вначале показывается **ориентир по паспортной автономности**, рассчитанный как `(процент − 1) × ресурс полного заряда / 100`. По умолчанию ресурс — 110 ч для обычной Pro и 140 ч для 35K, паспортные значения Razer для HyperSpeed при 1000 Гц. Это не измеренная автономность вашей конфигурации: подсветка, частота, износ и режим работы меняют расход.
- В настройках доступны профили 32 / 60 / 110 ч для обычной Pro, 28 / 60 / 140 ч для 35K и изменение по одному часу. 32/28 ч — паспортные ориентиры для 8000 Гц; 60 ч — пользовательский промежуточный профиль. Установите ресурс, похожий на ваш реальный опыт, пока приложение учится. История разряда и настройки ресурса для двух моделей разделены.
- После непрерывного участка разряда длительностью от 30 минут и падения минимум на 8 из 255 единиц (~3%) приложение использует линейную регрессию измерений. Необходимо накопить этот участок с работающим приложением.
- Зарядка, рост уровня или пробел в измерениях больше 10 минут прерывают участок. Прогноз учитывает время между замерами, включая короткие периоды бездействия. Это ориентир при похожем использовании, без обещания точного времени отключения.
- Во время подтверждённой зарядки прогноз разряда скрывается. Короткий сбой чтения не меняет процент и не скрывает последний прогноз. После повторных неудач последнее значение становится серым с подписью «Последний заряд»; время успешного чтения видно в подсказке значка. Прогноз при этом относится к последнему известному уровню, а не к текущему измерению. Неизвестное состояние зарядки повторно запрашивается и отмечается в подсказке.

## Ресурсы и данные

C++17, Win32, Direct2D (программная отрисовка), DirectWrite. Без Electron, WebView, .NET и сторонних библиотек. Один рабочий поток ждёт между опросами; обычный интервал 2 минуты, экономный — 5 минут. Обновление вручную ограничено одним запросом в 5 секунд. Анимация ease-out-quint длится 320 мс при открытии панели или страницы; после закрытия освобождаются графические объекты и шрифтовый кэш. Системное отключение анимаций соблюдается. При 15% показывается одно уведомление за цикл разряда.

В версии 1.3.1 возле мыши — рассеянный перламутровый свет с едва заметным зелёным оттенком: два мягких градиента медленно переливаются и смещаются на несколько пикселей, цикл изменения яркости — 9 секунд. Сама фотография остаётся неподвижной, её выравнивание с числом сохраняется. Эффект работает с частотой до 30 кадров/с только на открытой главной странице; перерисовывается лишь область возле мыши. В настройках и в трее таймер эффекта остановлен. При отключении анимаций в приложении или Windows остаётся статическое мягкое свечение.

Все данные локальны: `%LOCALAPPDATA%\BasiliskPulse\history.tsv` и `history-35k.tsv` (максимум 30 дней / 15000 замеров на модель), `status.json` (последнее чтение). Предпочтения — `HKCU\Software\BasiliskPulse`. Сетевых запросов и телеметрии нет.

В версии 1.4 последнее успешное измерение атомарно сохраняется в `last-reading.tsv` и восстанавливается при обычном запуске. Неудачный запрос не перезаписывает этот файл. Для существующих установок без файла кэша используется последнее реальное измерение из истории соответствующей модели. Восстановленное значение не считается свежим до успешного ответа устройства.

Временные HID-ошибки отправки и запоздавшие/занятые ответы повторяются внутри запроса. Если запрос всё же не удался, следующие попытки идут через 2, 5, 15, 30 и 60 секунд, затем возвращаются к настроенному интервалу. Во время восстановления активность мыши или клавиатуры обнаруживается без перехватчиков ввода и вызывает дополнительную попытку не позднее чем через 5 секунд. Открытие панели, подключение устройств и выход из сна также инициируют чтение. При нормальной связи сохраняется обычный экономный интервал.

В `status.json` поле `connected` означает успех последней попытки чтения. При неудаче `percent`, `raw`, `pid` и `unixTime` сохраняют последнее успешное измерение; время попытки записано в `attemptUnixTime`, число сбоев — в `consecutiveFailures`, задержка следующей попытки — в `retrySeconds`.

В версии 1.0 на этом ПК после открытия и закрытия панели: около 34 МБ working set и 8 МБ private bytes; за 54 секунды ожидания прирост CPU time составил 0 с. Память включает загруженные системные библиотеки; значения зависят от состояния Windows и шрифтового кэша. Это короткий замер, а не длительный нагрузочный тест.

В версии 1.1 удалены второстепенные подписи, обе страницы стали компактнее: окно 320×344 логических пикселя вместо 392×608 (на 54% меньше по площади; физический размер зависит от масштаба Windows). Вместо схематичной мыши встроена фотография с прозрачностью: небольшой PNG 256×437, который декодируется при открытии панели и освобождается при закрытии. Исходный вырезанный PNG и промпт обработки сохранены в `assets/`.

В версии 1.2 уменьшены шрифты кнопок и прогноза. Подпись карточки — «ДО 1% ЗАРЯДА», значение времени — «≈ … ч». В 1.2.3 число предварительно отрисовывается в прозрачный растр при текущем DPI, затем пустые строки и столбцы обрезаются по альфа-каналу. Фотография также обрезается после уменьшения и рисуется с теми же верхним и нижним краями, что и готовое число. Результат кэшируется до смены заряда, цвета или DPI и освобождается при закрытии панели. Две проверочные направляющие доступны при запуске с `--inspect --alignment-guides`; при обычном запуске их нет. Модель автоматически определяется по USB PID, название и профили автономности соответствуют подключённой мыши.

## Сборка и проверка

Нужны Visual Studio Build Tools с C++ x64 и Windows SDK. Запустите `build.ps1` в PowerShell. Скрипт собирает программу со статическим CRT и запускает тесты в `build\tests.exe`. `build\tests.exe --probe` выводит HID-интерфейсы и реальный заряд. `BasiliskPulse.exe --inspect` открывает панель для проверки UI без автоматического скрытия.

Тесты покрывают регрессию, квантование заряда, зарядку, плоскую кривую, пробелы, скачки, неизвестное состояние зарядки, порог 1%, проверку CRC, статуса и команды HID, поддерживаемые PID и разделение профилей моделей. Дополнительно проверяются краткий и длительный сбой, сохранение процента и времени замера, восстановление ответа, частичный ответ зарядки, смена модели, интервалы повторов, перезапуск с кэшем, 0% и повреждённый файл. Прямое чтение проверено на подключённой мыши `1532:00AB`. 35K реализована по известному протоколу и PID, но на физической 35K ещё не проверена. Физическое подключение кабеля и полный цикл разряда требуют дальнейшего использования; алгоритм проверен на синтетических последовательностях.

## Протокол и совместимость

Поддерживаются USB PID `00AA` / `00AB` (Pro, кабель / HyperSpeed), `00CC` / `00CD` (Pro 35K) и `00D6` / `00D7` (35K Phantom Green). Проводная Basilisk V3 35K без Pro (`00CB`) исключена: у неё нет аккумулятора. Bluetooth и Mouse Dock Pro с отдельным PID не поддерживаются. Приложение перечисляет HID через SetupAPI, проверяет VID/PID через `HidD_GetAttributes`, открывает коллекцию мыши с `desiredAccess=0`, отправляет только запросы батареи `07:80` и зарядки `07:84`, transaction ID `1F`. Проверяются команда, статус, transaction ID и CRC ответа. Настройки мыши не изменяются.

Структура протокола сверена с [OpenRazer](https://github.com/openrazer/openrazer/blob/master/driver/razerchromacommon.c), [PID моделей](https://github.com/openrazer/openrazer/blob/master/driver/razermouse_driver.h); реализация написана отдельно. Паспортные ориентиры: [Razer Basilisk V3 Pro — Support & FAQs](https://mysupport.razer.com/app/answers/detail/a_id/6219), [Razer Basilisk V3 Pro 35K](https://www.razer.com/gaming-mice/razer-basilisk-v3-pro-35k).
